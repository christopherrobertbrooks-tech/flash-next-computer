# Stage 5 plan: is the computer useful? (draft for Chris, 2026-10-30)

## The question
On a fixed set of questions, does Flash-Next Coder get more right with the exact computer than it does alone, or with
an ordinary Python calculator, and what does that cost in time and memory?

## Three setups (everything else identical)
Same Strata 0.1.41 build, same model, vision off, all 12,288 experts on the card (stage 4 showed this layout holds in
all three), temperature 0, the same prompts, one fresh Strata launch per setup:

| Setup | Tools offered |
|---|---|
| **A. Alone** | none |
| **B. Python** | `calc`, answered by host Python, with the same input rules as the computer (stage 4 contract) |
| **C. Computer** | `calc`, answered by the exact computer, every token checked against the reference machine |

The answer budget goes up from 3,000 to 8,192 tokens, so thinking doesn't get cut off the way the haiku was.

## The questions: 140, generated by a script with a fixed seed, frozen before any run
| Group | Count | What it tests | How it's scored |
|---|---|---|---|
| 1. Exact arithmetic | 50 | big multiplications, floor division, remainders, powers, gcd, fractions, decimals (10-40 digits) | the final `ANSWER:` line equals the exact value |
| 2. Near the computer's limits | 10 | long expressions, big powers: where the computer says "too complex" and Python doesn't | same; shows how often the limits bite |
| 3. Word problems, 2-5 steps | 40 | everyday-sounding problems needing exact big numbers ("48,213 crates of 1,237 units ...") | same |
| 4. Long chains | 20 | 8-15 small steps in a row (a running total) | same |
| 5. Normal requests | 20 | small Python functions with hidden unit tests, plus short explanations | the code passes its tests (run on the gateway inside the `sandbox-run` wall); for explanations, no tool should be called |

Group 5 checks that offering a tool doesn't make normal work worse, or tempt Flash-Next into needless calls.

## What gets measured
- **Right or wrong**, per question and setup, using the stage 4 checker (exact `ANSWER:` value; tool and answer verdicts
  kept separate).
- **Why it failed**, sorted into fixed classes: no ANSWER line, wrong value, tool refused or erred, the computer's
  limit, the computer and the reference disagreeing (must be **zero**), loops (the same call repeated, or the 8-round
  cap hit), cut off, server error.
- **Time** per question (wall clock), tool calls per question, time inside the tool.
- **Memory**: V100 peak, host RAM, expert slots, and the computer's own speed.

## What counts as a result (decided now, before any run)
- **"The computer helps"** = setup C gets more questions right than B, measured on the *same* questions (an exact
  paired test, p < 0.05), at a time cost that stays practical (written down per question).
- **"Equal"** = no significant difference between C and B. This is the most likely outcome: both tools return the
  same numbers, and stage 4 showed identical replies on its prompts. That would be a real, honest result: the bridge
  works and matches Python, but adds nothing except checkability, at seconds per call instead of milliseconds.
- **"Tools help"** (C or B vs A): reported separately; expected on big numbers.
- Every number is reported per group, with every failure listed; no single headline number hides a group.

## Stop rules
- Any disagreement between the computer and its reference machine: stop and investigate before going on.
- More than 5% server or harness errors in any setup: stop, fix the harness, restart that setup.
- **Pilot first:** 15 questions (3 per group) in all three setups (~20 min). If the scorer or timings look wrong,
  fix them before the full run.

## Cost
About 140 questions x 3 setups x ~20-40 s each: **roughly 3-4 hours of V100 time**, one job in the V100 lock (the
4070 and Sprocket's voice are untouched). Good for an overnight run.

## Honest limits, stated up front
- **The plan's "predicted advantage" can't be tested with this computer.** The plan guessed the computer might win by
  keeping exact state across many small steps. But the calc firmware has no memory between calls (each call starts
  fresh, like Python's calculator), so group 4 tests chained calls, not stored state. A computer with memory needs
  new firmware with variables: a separate, bigger project, only if you want it.
- A Python **code sandbox** (running whole scripts, not just expressions) would likely beat both calculators. It's
  left out to keep the comparison fair (same tool shape); it could be a fourth setup later.
- One answer per question at temperature 0: the uncertainty comes from the spread of questions, not from repeated
  sampling. One extra repeat of setup B checks that the runs are deterministic.

## What you'll have at the end
A results page: a table per group (right answers for Alone / Python / Computer), the time each setup took, memory, the
failure list, and a plain verdict on whether the computer is worth it. All raw replies saved.
