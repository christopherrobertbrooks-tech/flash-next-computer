## 3. Reference service and corpus

The ordinary well-formed path has a useful check: upstream `bridge.Session.qwen` produces the reference stream on `</tool_call>`, then `call()` compares each emitted chip/text stream token before accepting it, stops on mismatch, and rejects an early handback if expected tokens remain. Qwenputer's reference is a separate RV machine, not merely the GPU executor comparing with itself. This checks emitted token identity, not every internal tensor/state value or all possible firmware programs.

Independently recounted JSON: 89 calls, 88 without reference errors, 86 `agrees_with_python`, 319,722 chip tokens, matching the recorded summary. The corpus is 70 seeded generated cases (7 each across 10 kinds), 11 malformed/edge cases, 5 calls in one session, 2 long-input cases, and 1 intentional budget stop. The nonagreements are whitespace `  42  ` (circuit `42`, Python helper `error`), long-input error wording, and the deliberate budget stop. They are not recorded trace mismatches. The sequence demonstrates five calls can share the parked machine, not persistence of user-defined variables or recovery from a failed call. No Flash-Next-produced calls, transport routing, cancellation, concurrent clients or untouched control-path comparison are in this corpus.

## 4. Findings before stage 4

1. **REDLINE — reference output during input feeding can be discarded.** Spec: “Compare every computer step with the reference” and validate invalid syntax. Draft: `computer/computer.py:call`, `expect = list(self.lock.toks[k + 1:])` is overwritten for each input token; `_step(q)` output is inspected only after all input tokens. Upstream `bridge.Session.qwen` executes on every close-call token. Since `expr` is interpolated without rejecting protocol delimiters, a close-call token inside it can trigger a reference run before the wrapper's final close. Those expectations are overwritten and GPU predictions from intermediate input tokens are not consumed/checked. Also no response frame can still yield `error=None` if `expect` is empty. A CPU probe executing the actual `call()` AST with a fake tokenizer/reference/step demonstrated earlier reference output discarded and `{result: None, error: None}` returned. This establishes control-flow behavior, not an actual GPU delimiter exploit. **Smallest fix:** reject embedded protocol/special tokens for the expression-only API; require reference/circuit silence while feeding non-final input, execute/check at the single final delimiter, and require exactly one complete response before success. Add tests for embedded close/open tokens, unexpected ownership and missing response. Confidence: high.

2. **REDLINE — budget is not an end-to-end bound, and failures leave divergent machines reusable.** Spec: “long-running/budget stops,” state reset and correct sequences. Draft: `self.lock.qwen([q])` runs the reference ahead (default up to one million RV records) before `max_chip` is enforced in the GPU loop. The recorded 50-token budget returns after counting 51 chip tokens. After a budget/mismatch return, reference state has advanced to the end while executor state has not, and `self.lock` remains callable. The test intentionally stops last and never tests recovery. **Smallest fix:** explicitly invalidate the session on every aborted/mismatched/reference-error call and require `new_session()` before reuse; bound input length, reference work, total emitted tokens and elapsed time, with a documented budget definition. Do not return partial result text as successful output. Test call-after-abort, reference timeout and mismatch, reset, and fresh-session equivalence. Serialize the single mutable instance or allocate per-session state before exposing concurrent callers. Confidence: high from control flow; no live recovery run performed.

3. **REDLINE — test runner does not enforce the advertised gate.** Spec: “Gate: zero observed trace mismatches … correct call/result routing.” Draft `computer/test_computer.py` prints `ERR`, writes summaries, and returns normally regardless of unexpected errors or wrong answers; `executor_footprint.py` similarly catches mismatch assertions and continues. A CPU probe executed the actual test `main()` with a failing fake service: all 20 probe calls reported injected mismatches, `reference_clean=0`, and it still returned normally. **Smallest fix:** declare expected per-case status/results, assert corpus counts and required fields, distinguish intended budget/error cases, and exit nonzero on any unexpected failure. Add deliberate mismatch/early-handoff/wrong-answer controls proving the runner fails. Preserve the saved raw results; this finding does not turn their 88 clean calls into failures. Confidence: high.

4. **REDLINE — resource and isolation gates are not yet complete.** Spec: stage 2 requires a byte budget and matched measurements; stage 3 requires measured peak VRAM/RAM, latency and idle behavior. Draft scripts measure a holder beside Strata rather than the actual checked service, only one short cold prompt, sampled device VRAM and host snapshots; no computer+vision run or trace-isolation handoff proof exists in these outputs. **Smallest report wording:** “Short-prompt coexistence was demonstrated with vision off. The real service's peak/idle host and GPU budget, vision coexistence and pause/resume isolation remain unverified.” Before attachment, obtain those measurements and enforce a resource/admission policy; full-context support cannot be inferred from `--max-context 131072`. Confidence: high.

5. **NIT — benchmark harness can hide failed requests and leave workloads on abort.** `strata_mem_test.sh` uses `set -uo pipefail` without checking curl HTTP status or JSON schema; null content raises a printer error; readiness failure kills only the monitor and can leave the companion process. Normal cleanup uses a broad pattern rather than a recorded child process group and there is no EXIT/INT/TERM trap. **Smallest fix:** retain exact owned child/group IDs, install cleanup traps, verify readiness belongs to the spawned instance, check HTTP/JSON/error/finish fields, and print nullable content safely. Treat cancellation and failed-start trials explicitly; never apply cleanup to unrelated/resident services. Review-only: no cleanup commands were run. Confidence: high.

6. **NIT — isolated memory labels and test coverage need narrower wording.** Spec asks for computer “weights and state, temporary workspace and margin.” `executor_footprint.py` calls its post-query 60 MiB delta “CUDA context of this process” and reports a Torch allocation peak as one memory figure; only one CRC trace is checked here. **Smallest fix:** label the delta exactly as measured, report process/device/Torch allocated/reserved peaks separately, and state the program and timing boundary beside each throughput number. Keep the checked service's ~190.9-second corpus timing separate from the raw executor replay rate. Confidence: high.
